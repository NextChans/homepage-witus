# 12. 빈 프로젝트에서 여기까지 — 단계별 재현

**이 사이트를 처음부터 다시 만든다면 어떤 순서로, 각 단계에서 무엇을 놓치면
안 되는가.** 코드 설명이 아니라 **순서와 함정**이 내용이다. 코드는 저장소에
있고, "왜" 는 `doc/04-decisions.md` 에 있다.

> 새 프로젝트에 이 구조를 이식할 때도 이 순서를 따르면 된다.

---

## 0. 순서가 왜 중요한가

이 프로젝트에서 **되돌리기 비싼 것부터** 정해야 한다.

```
콘텐츠 구조 → 디자인 토큰 → 페이지 → DB → 관리자 → 알림 → 도메인 → 공개
   싸다                                                        비싸다
```

거꾸로 가면 — 예컨대 도메인부터 붙이면 — **확정되지 않은 값이 실제 주소로
나가기 시작한다.** 실제로 이 프로젝트가 그 순서를 어겼고, 플레이스홀더가
운영 사이트에 노출됐다(ADR-028).

---

## 1. 스캐폴딩

```sh
npx create-next-app@latest --typescript --tailwind --app --eslint
```

**바로 정할 것**

- `tsconfig.json` 에 `strict` + **`noUncheckedIndexedAccess`**.
  나중에 켜면 수백 곳이 깨져서 못 켠다.
- Tailwind v4 는 `@theme` 블록으로 토큰을 정의한다(설정 파일이 아니다).

⚠️ **`noUncheckedIndexedAccess` 를 켜면 배열 인덱스 결과가 `T | undefined` 다.**
`arr[0]` 을 그냥 쓰던 습관이 전부 걸린다. 그 대가로 "있을 줄 알았는데 없었다"
류의 런타임 오류가 사라진다. 처음에 켜는 것이 유일하게 싼 시점이다.

## 2. 콘텐츠를 코드에서 분리한다 ← **가장 먼저**

`content/` 에 데이터 모듈을 만들고 **페이지에 문안을 하드코딩하지 않는다.**

```
content/site.ts       회사 정보·메타
content/services.ts   서비스 정의
content/brand.ts      로고 도형·아이덴티티 색
content/features.ts   기능 플래그
```

**왜 먼저인가** — 나중에 분리하려면 모든 페이지를 다시 열어야 한다. 그리고
이 프로젝트에서 실제로 가장 자주 바뀐 것이 **문안과 회사 정보**였다.

### ⚠️ 미확정 값은 플레이스홀더가 아니라 `null` 로

```ts
bizNo: null,      // ❌ '000-00-00000'
address: null,    // ❌ '서울특별시 강남구 테헤란로 000'
tel: null,        // ❌ '02-0000-0000'
```

플레이스홀더의 수명은 **"도메인이 붙는 순간"** 까지다. 그 뒤로는 더미가 아니라
**허위 표시**다. 특히 `tel:02-0000-0000` 은 **누르면 실제로 전화가 걸린다** —
표시 오류가 아니라 동작하는 결함이다.

`null` 로 두면 타입이 `string | null` 이 되어 **화면이 null 처리를 강제당한다.**
빠뜨릴 수 없다. (ADR-028)

### ⚠️ 숨길 수 있는 섹션은 **자기 크롬을 자기가 소유한다**

```tsx
// ❌ 호출부에 래퍼 — 컴포넌트가 null 을 반환해도 빈 띠가 남는다
<div className="border-t bg-surface"><LogoStrip /></div>

// ✅ 컴포넌트가 래퍼까지 갖는다
export function LogoStrip() {
  if (!features.partnerLogos) return null
  return <div className="border-t bg-surface">…</div>
}
```

실제로 전자로 만들었다가, 플래그를 끄자 **높이 1px 짜리 빈 띠**가 남아 구분선이
두 줄로 겹쳤다. 스크린샷으로는 안 보여 DOM 을 재서 찾았다. (ADR-035)

## 3. 기능 플래그

`content/features.ts` 에 **코드 상수**로 둔다. 환경변수가 아니다.

- 켜고 끄는 판단이 **컴플라이언스 결정**이다 — 대시보드에서 조용히 바뀌면 안 되고
  PR 로 검토·기록되어야 한다.
- 환경변수는 빌드 시점에 값이 없으면 **켜진 채로 빌드될 수 있다.**

```ts
type Features = { inquiryForm: boolean; /* … */ }   // ← boolean, as const 아님
```

⚠️ **`as const` 를 쓰지 않는다.** 리터럴 `false` 로 좁혀지면 **비활성 분기가 죽은
코드가 되어 타입 검사에서 빠진다.** 나중에 켜는 순간 깨진다.

⚠️ **그 대가로 트리셰이킹은 안 된다.** 끈 기능의 모듈 코드는 번들에 남는다.
동작이 멈추는 근거는 "사라져서" 가 아니라 **"렌더되지 않아서"** 다. 이걸 헷갈리면
"번들에 남아 있는데 정말 꺼진 건가" 하고 플래그를 믿지 못하게 된다. (ADR-033)

## 4. 디자인 토큰

`app/globals.css` 의 `@theme` 에만 색을 둔다. **컴포넌트에 `#hex` 를 쓰지 않는다.**

⚠️ **Tailwind 는 클래스 문자열을 정적으로 스캔한다.** `grid-cols-${n}` 처럼
조립하면 **CSS 가 생성되지 않는다.** 개수에 따라 열을 바꾸려면 정적 맵을 쓴다.

```ts
const GRID_COLS: Record<number, string> = { 3: 'grid-cols-1 sm:grid-cols-3', … }
```

## 5. 페이지

하위 페이지 히어로는 `<Hero size="headline">`. `display` 스케일은 홈 전용이다 —
**한국어가 3줄로 깨진다.**

⚠️ **긴 한국어 제목은 줄바꿈을 명시한다.** 브라우저에 맡기면 1440px 에서도
의도와 다르게 끊긴다. 320 / 390 / 768 / 1440 에서 실제로 재 보고 정한다.

## 6. Supabase

`supabase/migrations/` 에 번호순 SQL 을 둔다. **대시보드 SQL Editor 로 적용하면
비밀키가 전혀 필요 없다** — 채팅·커밋에 키가 오갈 일이 없어진다.

### ⚠️ SQL Editor 는 마지막 문장 결과만 보여준다

앞 문장이 실패해도 화면에는 `Success` 만 뜬다. 실제로 cron 등록이 이렇게 조용히
안 걸렸다. **중요한 문장은 하나씩 실행하고 반환값을 본다.**

### ⚠️ 적용 후에는 만들어진 객체를 **직접 센다**

`Success` 를 믿지 않는다. → `doc/11-sql-runbook.md` 2절

### 보안 기본값

```
public.inquiries       RLS on + 정책 없음  (service_role 로만 접근)
원문 IP                저장하지 않는다 — salt + SHA-256 해시만
주민번호·계좌·카드번호  애초에 받지 않는다
```

⚠️ **salt 없는 IP 해시는 사실상 재식별 가능하다.** salt 가 없으면 해시도 만들지
않는 쪽이 맞다.

## 7. 파기 잡 (pg_cron)

보관기간이 지난 데이터를 지우는 잡. **"3년 보관" 을 처리방침에 쓰면 실제로
지워야 한다** — 적어 두고 안 하는 것이 위반이다.

⚠️ **cron 표현식은 UTC 다.** `10 18 * * *` = 03:10 KST. KST 로 적으면 9시간 어긋난다.

⚠️ **`cron.job` 이 0행이어도 "없다" 고 단정하지 않는다.** pg_cron 1.4+ 는
`username = current_user` 정책이 걸려 있어 롤이 다르면 안 보인다.
→ `doc/11-sql-runbook.md` 5절로 구분한다.

⚠️ **등록됐다고 도는 것은 아니다.** 최종 확인은 **다음 날** `data_retention_log` 에
`triggered_by = 'cron'` 행이 생기는지 보는 것이다. 삭제 대상이 없으면
`deleted_count = 0` 행이 남는데 **그 0 행이 유일한 증거다.**

## 8. 관리자 화면

⚠️ **가드는 레이아웃이 아니라 각 페이지에서 호출한다.** App Router 레이아웃은
클라이언트 네비게이션에서 매번 재실행된다고 보장되지 않는다.

⚠️ **권한 부족은 403 이 아니라 `notFound()`.** "여기 관리자 화면이 있다" 는 사실
자체를 알려줄 이유가 없다.

⚠️ **Server Action 은 폼 없이도 직접 POST 될 수 있다.** 화면을 가리는 것으로는
부족하고 **액션 안에서 세션·권한을 다시 확인**해야 한다.

## 9. 알림 — **조용한 실패를 만들지 않는다**

접수 알림은 **실패해도 throw 하지 않게** 만든다. 알림 실패가 접수를 실패시키면
안 되기 때문이다. 옳은 설계지만 **부작용이 크다 — 웹훅이 틀려도 증상이 없다.**

> **실패해도 throw 하지 않는 경로에는 수동 점검 수단을 함께 둔다.**
> "조용히 안 온다" 는 가장 나쁜 실패 형태다. 침묵을 깰 방법이 없으면
> 그 설계는 절반만 끝난 것이다. (ADR-030)

이 프로젝트는 `/admin` 에 **"테스트 메시지 보내기"** 버튼을 뒀다. 실패 이유를
구분해 돌려준다(미설정 / HTTP 오류 / 예외) — **그 구분이 기능의 존재 이유다.**

⚠️ **알림에 개인정보를 넣지 않는다.** Slack 은 제3자 서비스이고 메시지는 장기
보존·검색된다. 이름·연락처·본문을 넣으면 **처리방침의 수탁자 목록에 Slack 을
추가**해야 한다. 분야·회사명·접수 id 만 보내고 내용은 대시보드에서 본다.

→ 이 원칙 덕분에 **접수 채널을 여러 사람에게 열 수 있다.**

## 10. 도메인 — **여기부터 되돌리기가 비싸다**

⚠️ **도메인을 붙이기 전에 2절의 플레이스홀더 정리를 끝낸다.** 붙는 순간부터
모든 더미 값이 실제 주소로 나간다.

순서:
1. `witus.kr` 이 **열리는 것을 먼저 확인**한다
2. 그 다음 `www` 와 `*.vercel.app` 을 **308 영구 리다이렉트**로 모은다
3. 경로가 보존되는지 잰다 (`www/services` → `witus.kr/services`)

⚠️ **본체 행을 리다이렉트로 바꾸면 자기 자신으로 보내 사이트가 죽는다.**
Vercel Domains 화면에서 세 행이 똑같이 생겨 헷갈린다.

⚠️ **canonical 은 상대 경로로 둔다** (`alternates: { canonical: './' }`).
절대 URL 로 두면 **모든 페이지가 홈을 가리킨다.**

## 11. 공개 전 — 법적 표시

| 항목 | 조건 |
|---|---|
| 상호에 `주식회사` | **설립등기 후.** 상법 제20조 — 회사가 아니면 쓸 수 없다 |
| 사업자등록번호·주소 | 사업자등록 후. 전자상거래법상 사업자 표시 |
| 개인정보처리방침 공개 | **개인정보를 수집하기 전.** 법정 기재사항에 사업자등록번호는 없다 |
| 국외 이전 고지 | 수탁자가 국외 법인이면 **법 제28조의8 ② 5개 항목 전부** |

⚠️ **"수집은 하는데 처리방침이 비공개" 상태를 만들지 않는다.** 쿠키가 없어도
마찬가지다 — 문제는 식별 가능성이 아니라 **공개하지 않은 채 수집하는 것**이다.
처리방침을 아직 못 올리면 **수집을 멈춘다.** (ADR-033)

⚠️ **`100% 승인` · `반드시 통과` · `최저 수수료 보장` 류의 단정·최상급 표현을
쓰지 않는다.** 전자금융 도메인에서 표시광고법 리스크다. 근거 없는 수치도 같다 —
**숫자를 만들지 말고 그 항목을 지운다.**

## 이 프로젝트에서 반복된 실패 한 가지

**조용한 빈 값을 정상 데이터로 읽는 것.** 세 번 겪었다.

| 무엇 | 어떻게 드러났나 |
|---|---|
| Slack 알림 실패 | throw 하지 않아 화면상 증상 없음 → 점검 버튼을 만들어 해결 |
| 정적 grep 으로 플래그 확인 | 켠 빌드·끈 빌드가 **같은 결과** → 아무것도 증명 못 함 |
| GitHub API 가 `301` 반환 | `-L` 이 없어 본문이 비었고 → "CI 가 아직 실행 중" 으로 오인 |

> **측정이 판별력을 갖는지 먼저 확인한다.** 대조군을 세워 "달라야 하는 쪽이
> 실제로 다른가" 를 본 뒤에 결론을 낸다. 응답이 비면 파싱 결과를 믿기 전에
> 상태 코드를 본다.
