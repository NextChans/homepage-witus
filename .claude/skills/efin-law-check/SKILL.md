# 전자금융거래법 원문 대조

`content/eligibility.ts` 는 **금액과 조문을 코드에 박아 둔 파일**이다. 법이 바뀌면
자동으로 틀리는 종류의 코드이므로, 개정 때마다 이 절차를 돌린다.

## 0. 왜 검색으로 때우면 안 되는가

2026-09-14 대조에서 **공개 자료만 보고 쓴 초안에 오류 4건**이 나왔다. 전부 "숫자는
맞는데 붙는 자리가 틀렸다" 였고, 그중 하나는 **판정이 정반대**였다.

| 초안 | 원문 |
|---|---|
| 선불 "다른 곳 1군데면 면제" | 하나의 가맹점 **사업주가 동일한 경우로 한정** (법 §28③1가) |
| 2026.12.17에 중개 부수정산 **제외** | 정보만 전달하는 PG 면제가 **삭제** (법 §28③2) |
| 분기 총액 300억 | 현행 **30억**, 300억은 개정 신설 구간 (법 §30③) |
| 선불충전금 100%는 개정 의무 | **현행 의무** (영 §13의2②) |

로펌 해설·블로그는 요약이라 이 차이가 사라진다. 실제로 토스 블로그는 선불 면제를
`또는` 으로 썼는데 법 §28③1나 원문은 `및` 이다.

## 1. 원문을 구한다 — **직접 못 가져온다**

법제처(`law.go.kr`)는 본문을 AJAX 로 채우는 SPA 다. 세 경로 모두 실패한다:

| 방법 | 결과 |
|---|---|
| `curl https://www.law.go.kr/...` | `Connection reset by peer` (프록시 차단) |
| `WebFetch` 법제처 | 제목만, 본문 없음 |
| `WebFetch` `elaw.klri.re.kr` 미러 | "본문 검색결과가 없습니다" |

→ **사용자에게 PDF 를 요청한다.** 법제처 화면 우측의 저장/인쇄로 받을 수 있다.
받을 것은 셋이다:

1. 전자금융거래법 — **현재 시행 중인 버전**
2. 전자금융거래법 — **시행 예정 버전** (있으면. `LAW_BASIS.upcoming` 의 근거)
3. 전자금융거래법 **시행령** — 금액은 대부분 여기 있다
4. **전자금융감독규정**(금융위 고시) — 산정방법·기한은 여기 있다

⚠️ 시행 예정 버전을 빼먹으면 안 된다. 위 오류 2번이 바로 그것이다 —
**현행 본문에는 삭제 예정 조항이 멀쩡히 남아 있다.**

## 2. 텍스트로 뽑는다

컨테이너에 `poppler-utils` 가 없다. `pypdf` 는 `cryptography` 네이티브 모듈이 깨져
있어 못 쓴다.

```sh
apt-get update -q && apt-get install -y -q poppler-utils
pdftotext -layout input.pdf out.txt
```

⚠️ `apt-get update` 를 먼저 해야 한다. 바로 install 하면 404 가 난다.
⚠️ `-layout` 없이 뽑으면 항·호 들여쓰기가 뭉개져 "②의 1호" 같은 걸 못 읽는다.

조문 목록부터 본다:

```sh
grep -n "^ *제[0-9]*조" out.txt
awk '/^제28조\(/,/^제31조\(/' out.txt
```

## 3. 대조할 자리

`content/eligibility.ts` 의 각 `Verdict.lawRef` 가 그대로 체크리스트다.

| 값 | 근거 |
|---|---|
| 선불 면제 금액 (발행잔액 / 연간 총발행액) | 법 §28③1나 · **영 §15⑤** |
| 선불 1가맹점 면제 (사업주 동일) | 법 §28③1가 |
| PG 면제 (정보만 전달) | 법 §28③2 · **영 §15⑦** |
| 결제대금예치·전자고지결제의 정의 | 법 §28②5 · **영 §15③** |
| 자본금 — 이체/직불/선불 | 법 §30② · **영 §17①** |
| 자본금 — PG/예치/고지결제 구간별 | 법 §30③ · **영 §17②③** |
| 자본금 합산·50억 상한 | **영 §17④** |
| 분기 거래총액 구간 경계 | 법 §30③ · **고시 §42의2①** |
| 소규모 등록 후 초과 시 요건 충족 기한 | 법 §30④ · **고시 §42의2②** |
| 선불 발행잔액·총발행액 **산정방법** | **고시 §42①** |
| 선불충전금 별도관리 비율 | 법 §25의2① · **영 §13의2②** |
| 정산대상금액 외부관리·경과규정 | 법 §25의4 · **부칙** |
| 대주주 변경 신고기한 | 법 §33의3 |

**금액은 거의 전부 시행령에 있다.** 법률은 하한만 정하고 "대통령령으로 정하는
금액" 으로 넘긴다. 법률만 보면 PG 자본금을 5억으로 적게 된다(실제 영 §17③은 10억).

**부칙을 반드시 읽는다.** 경과규정·유예기간은 본문에 없다.

**금액이 아니라 "무엇을" 세는지도 본다.** 2026-09-14 2차 대조에서 제일 위험했던 것이
이것이다 — "분기별 전자금융거래 총액" 으로 물었는데 고시 §42의2①의 기준은 **업종별
금액**이고 결제대행금액은 **이용자가 지급한 재화·용역의 매출총액**이다. 담당자가 수수료
수익으로 답하면 자릿수가 통째로 틀린다. **조문의 요건 개수도 센다** — 영 §15③2호는
고지·자금 직접 수수·정산 대행 3요소인데 질문은 하나로 뭉뚱그리고 있었다.

**위임 규정을 못 찾으면 "못 찾았다" 로 둔다.** 법 §2⑭의 "대통령령으로 정하는
특수관계인" 은 시행령에도 고시에도 없었다. 이런 건 추정해서 판정하지 말고 질문 안내로
"모르겠다" 를 유도한다 — **없는 의무를 있다고 말하는 쪽이 더 나쁘다.**

## 4. 검증 — 페이지를 띄우지 말고 함수를 돌린다

`features.eligibilityCheck` 는 auto mode 에서 **쓰기가 차단**된다(Feature Flag
Writes). 플래그를 켜서 화면으로 확인하려 하지 말고 `evaluate()` 를 직접 돌린다.

```sh
mkdir -p "$SCRATCH/elig" && cp content/eligibility.ts "$SCRATCH/elig/"
# run.mts 에서 './eligibility.ts' 를 import
node --experimental-strip-types "$SCRATCH/elig/run.mts"
```

반드시 함께 검사할 것:

```ts
// 질문 키와 Answers 키가 어긋나면 그 질문은 답을 받아도 영영 unsure 로 떨어진다.
// 화면상으로는 멀쩡해 보이므로 눈으로는 못 잡는다.
Object.keys(EMPTY_ANSWERS).sort().join() === questions.map(q => q.key).sort().join()
```

시나리오는 최소 5개 — 각 업종 `likely` 1개씩, `exempt` 1개, **전부 `unsure`(기본값)**.

⚠️ **화면에 나가는 문자열에 마크다운 `**` 을 쓰지 않는다.** `/check` 는 마크다운을
파싱하지 않아 별표가 그대로 보인다. 주석에는 써도 된다.

```sh
# 코드 줄(주석 아님)에 ** 이 남았는지
grep -n "'" content/eligibility.ts | grep '\*\*'
```

## 5. 마무리

- `LAW_BASIS.checkedAt` / `current` / `upcoming` / `sources` 를 갱신한다.
  `sources` 는 **법령 번호와 시행일까지** 적는다 — 다음 사람이 같은 것을 다시 받는다.
- 판정이 바뀌었으면 `doc/04-decisions.md` 에 ADR 을 남긴다. 무엇이 틀렸는지
  표로 남긴다 — 같은 자리에서 또 틀린다.
- `features.eligibilityCheck` 는 **법무 검토 전까지 off 로 둔다.**
  원문 대조가 끝났다고 켜는 것이 아니다. 대조는 "조문을 옮겨 적은 게 맞다" 이고,
  검토는 "이 사업 구조가 그 조문에 걸린다" 다. 다른 이야기다.
